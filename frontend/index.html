Partitioning

A record's key is hashed with murmur2; partition = hash(key) mod N. Every reading of the same bin lands in the same partition, so per-bin ordering is guaranteed — exactly how bin-telemetry is keyed by bin_id.

Consumer groups

Each partition is owned by exactly one consumer of a group. Add or remove consumers and watch the rebalance (range assignor). More consumers than partitions ⇒ idle consumers. Slow consumers ⇒ lag = log-end offset − committed offset.

Replication

Each partition has a leader and followers on 3 brokers (RF = 3). Kill a broker: the controller elects a new leader from the ISR, producers and consumers fail over and no committed data is lost with acks=all.

Agent 1 · Waste Intelligence

WHAT needs attention? Scores every bin from fill level, sliding-window fill rate, overflow ETA, ward complaint history and anomalies → HIGH / MEDIUM / LOW.

0.35·fill + 0.35·urgency + 0.15·rate + 0.15·history

Agent 2 · Route Planner

HOW should we collect? Capacity-constrained clustering, opportunistic pickup of nearby bins, batching, nearest-neighbour + 2-opt sequencing, traffic-aware time, plant selection by utilisation.

road km = haversine × 1.35 · peak 14 km/h

Agent 3 · Fleet Manager

WHO collects it? Checks availability, capacity, current load and location of every truck; best-fit on dead-head km + spare capacity; supports dynamic insertion into running routes.

score = deadhead + 6·slack (+4 if busy)
